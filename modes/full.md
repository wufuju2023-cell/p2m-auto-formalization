# Mode `full` — statements plus proofs

Operational checklist for a chapter whose effective mode is `full`
(`book.json.mode === "full"` and no `chapter_modes[chapter]` override).

## Invariants

- Every theorem-like card ends at `status: "proved"`, `sorry_count: 0`.
- `Solutions/<lean_name>.lean` must contain zero `sorry`, zero `axiom`, zero
  `native_decide`, zero `unsafe`, and must not import its own statement module.
- `Theorems/<lean_name>.lean` is the statement artifact. It may keep one `sorry`
  while the proof lives in `Solutions/`.
- Definitions live in `Definitions/<lean_name>.lean` and must be `sorry`-free.
- `af_next` may return `sketch` and `prove`.
- `af_status` warns on `sorry` in any `Solutions/` file.

## Task order for one theorem-like card

1. `state` — write the formal statement in `Theorems/...` (or `Exercises/...`).
   Replace the `af:placeholder` sentinel and the placeholder type.
2. `af_check` on the statement file. The verdict is `OK_STATEMENT` when the file
   has at most one `sorry` and compiles.
3. `audit` — read the file against the source and write a readback with
   `af_record(kind="audit", item_id=..., text=...)`. No readback, no proof.
4. `sketch` — only when the card has children (`depends_on` edges from other
   theorem-like cards). One dispatch, recorded as a note.
5. `prove` — write `Solutions/<lean_name>.lean` with the same declaration and a
   real proof. Leaves are eligible immediately; parents wait until every child is
   `proved`.
6. `af_check` on the proof file. Success is `OK_PROOF` with `sorry_count: 0` and
   the card becomes `proved`.
7. `integrate` — when every card in the chapter is done, `af_mission` builds the
   public proposal.

## Per-card commands

```text
af_next(slug)                                  # claim define/state/audit/sketch/prove
af_check(slug, item_id, file?)                 # compile + policy scan
af_record(slug, kind="audit", item_id, text)   # readback
af_record(slug, kind="note", item_id, text)    # proof notes
af_export(slug, item_id)                       # solution.lean bundle
af_mission(slug, chapter)                      # public proposal + submit.sh
```

## File rules

| Item kind | Statement file | Proof file |
|---|---|---|
| definition | `Definitions/<name>.lean` | none |
| theorem / lemma / proposition / corollary / example / remark | `Theorems/<name>.lean` | `Solutions/<name>.lean` |
| exercise | `Exercises/<name>.lean` | `Solutions/<name>.lean` |

Names are generated by `af_ingest`:

- `Def_<chapter>_<section>_<Slug>`
- `Thm_<chapter>_<section>_<Slug>`, `Lem_...`, `Prop_...`, `Cor_...`, `Eg_...`, `Rmk_...`
- `Ex_<chapter>_<section>_<n>` for exercises

## Do not

- Do not add `sorry` to a `Solutions/` file "for later".
- Do not import `Theorems.<own name>` from its proof file.
- Do not use `axiom`, `native_decide` or `unsafe` to close a goal.
- Do not edit `plan.json` status by hand; `af_check` and `af_record` own it.
  (`depends_on` is the one architect-editable field.)
- Do not write outside the file named by `af_next`.
